# Spark 2.2.0 への更新（オンライン版）— 計測記録 2026-09-27

## 結論
- オンライン版（locahun3d.com の物件ページ・シーン編集）のレンダラーを **Spark 2.2.0 ＋ ワーカープール拡大 ＋ Range 取得 no-store** に更新し、
  LoD 走査は 2.2 の新方式 `lodTraverseMode: "dynamic"` を既定にする（`?lodTraverse=standard` で従来）。
- 2.0 系に当てていた独自の差分走査（Rust）と heap319 は持ち越さない。2.2 の dynamic 走査がそれより速い。
- 単体配布版（viewer.locahun3d.com / ZIP 配布）は 2026-09-13 の判断どおり元の 2.0 レンダラーのまま。

- `spark20-local-base*`: 現行 2.0改（heap319、no-store なし）。`spark20ns`: 現行オンライン版の実バンドル（heap319 + no-store）。
- `spark22w16-dynamic*`: 2.2 + プール拡大 + dynamic。`spark22ns-dynamic*`: それに no-store を足した **採用バンドル**。
- `spark22-standard` / `spark22w16-standard`: 2.2 の従来走査。2.0改より遅いので採らない。
- 1回ずつ「読込後に LoD が動かなくなる」回があった（base 1回目・22w16 2回目）。2.0/2.2 の両方で起きており計測環境側の揺れとみて除外。

### 読み方
- 振り向き後の収束（+90 / -90 / 戻る / 180再）は 2.0改 1.0〜2.1s → **2.2 dynamic 0.2〜0.8s**（3〜4倍速い）。
- 読込は同等。no-store 同士では読込後の最初の振り向きが 5.4s → 9.7s に伸びるが、2.0 が 2.50M 点で止まるところを 2.2 は一度に 5.01M 点まで詰めている（到達点が違う）。
- `perf-edge-lod.mjs` ＋ `edge-sharpness.py`（4方向の端/中央の精細さ）は **数値が同一**（平均 1.30 / 1.30）。見た目の劣化なし。
- エラー 0（全 15 回）。
